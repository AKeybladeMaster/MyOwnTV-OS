# PC toolchain and compatibility

The app's only runtime dependencies are the TV's web engine and public `PalmServiceBridge` / `webOSSystem` objects. The IPK has no npm packages, JS service, native executable, package scripts, or privileged permission. Content Security Policy forbids network connections and external resources. Six local photos account for almost all of the package size.

The PC toolchain is pinned in `package-lock.json`. Direct esbuild, Playwright, and ws versions were checked against npm and updated during development. `@webos-tools/cli` 3.2.6 is LG's supported CLI. Its published package bundles some older dependencies, which npm reports under `@webos-tools/cli/node_modules/`. A normal `npm audit fix` did not replace those bundled copies. The report includes brace-expansion/braces, js-yaml, proxy-addr, qs, and sprintf-js, plus their dependency paths. Do not state that the complete PC toolchain is free of advisories. This project does not expose the CLI's server to the LAN or accept untrusted package sources or glob patterns. Its preview server binds only to loopback and is implemented independently of those bundled packages. No force upgrade or unreviewed fork of LG's installer is used.

The packaging warning about `requiredACG` refers to newer webOS platform submission rules. [LG's ACG guide](https://webostv.developer.lge.com/develop/guides/acg-guide) states that webOS TV 25 and lower do not support ACG. This target is webOS 5. Its app metadata requests no privileged permissions. Public application launch is documented in [Application Manager](https://webostv.developer.lge.com/develop/references/application-manager), and Back handling follows [LG's Back button guide](https://webostv.developer.lge.com/develop/guides/back-button).

No Android, Google TV, or newer-webOS benchmark is presented as a performance result for this LG. Real-TV verification must record its exact firmware, what was actually launched and captured, and which checks still need the physical remote or a signed-in stream.
