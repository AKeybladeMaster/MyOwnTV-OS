# Prompt for an AI installation agent

Copy the block below into Claude, Codex, Antigravity, Grok or another agent with local terminal and LAN access. Start in a checkout of this repository. Keep account passwords and pairing secrets out of the prompt. A chat-only assistant should guide the owner through local commands instead of claiming to have executed them.

```text
Help me build and install MyOwnTV from this existing repository onto my LG webOS TV. Use the repository's implementation and guarded tools; do not rebuild the project from scratch. This request authorizes ordinary local build work, readable backups, pairing with my TV and installation of this standalone app. It does not authorize changes to other apps, firmware or native settings.

First read AGENTS.md, README.md, docs/installation.md, docs/safety-and-restore.md, docs/privacy-plan.md, docs/toolchain.md, config/target.json and the relevant tools. Inspect git status and preserve all local work. Explain that the existing verified target is LG 49NANO816NA / firmware04.64.00 / SDK5.6.2, not a universal compatibility guarantee.

Begin by helping me activate LG's official Developer Mode app using https://webostv.developer.lge.com/develop/getting-started/developer-mode-app . Have me create/sign in to the developer account directly on LG's site/TV, enable Dev Mode Status, complete its reboot, and reopen the app. Explain session renewal with EXTEND and the possibility of developer apps being removed when Developer Mode is disabled. Never ask for my LG account password. Retrieve the temporary SSH pairing phrase through a local interactive prompt, not in committed files or logs.

Inspect the computer's tools and existing webOS aliases before installing dependencies or pairing. Use the pinned package lock with npm ci. Identify my intended TV on my LAN; ask for its address/model if you cannot establish them. Never target a second TV merely because it responds. Use the official webOS SSH route (prisoner,9922), not ADB/root. Confirm actual model, firmware and SDK with ares-device and compare with the physical TV. For a different model, assess public API and engine compatibility before deliberately adapting config/target.json locally. Do not bypass identity checks. Preserve valid existing pairings and certificate pins.

Reuse an already-enabled Developer Mode setup. Before any manual Dev Mode Status, Key Server or Quick Access change, help me save its displayed original value/menu path and a before photo in an ignored private change record, then record the result afterward. Prerequisite photos can be taken physically before pairing; never disable a valid setup merely to repeat instructions.

Use the repository SSAP pairing/inventory flow, asking me to accept the prompt on the TV when needed. Keep all keys, IP addresses, raw inventories, captures, backups and deployment records private and ignored by Git. Never print credential files. Verify the actual installed app IDs. Ask which apps I want in my dock and adapt config/apps.json using installed, ordinary app IDs, keeping one to seven favorites. Preserve every installed app, LG Content Store, Developer Mode and native features. Do not assume the original owner's app choices or privacy permissions apply to me.

If adapting source catalog/defaults, review and update affected owner-requirement fixtures in tests/domain.test.mjs, tests/browser-flow.mjs and tests/file-origin.mjs to the newly confirmed app IDs, order and favorite count. Preserve validation/navigation coverage and never skip tests or remove safety assertions to force installation. In-app dock editing alone needs no source or fixture changes.

Run npm test, npm run package, npm run test:browser and npm run test:file, installing the appropriate test browser if needed. Explain which generated IPK is the TV artifact and that its assets are already bundled. Inspect the manifest/checksum and use the repository IPK validator. Take a fresh readable-state snapshot before installation. Explain that this is not a firmware or login-data backup. Use npm run tv -- install for a first installation, or the documented explicit update flow with retained prior IPK, matching deployment history and fresh own-app preference export. Never uninstall an app to bypass an update guard. Stop dependent work and explain any missing evidence.

Once the launcher is actually foreground, save and inspect an actual-TV app-viewport screenshot with tools/inspect-app.mjs --assert-rendered and a unique name. Check navigation, wallpaper changes and launch shortcuts. Ask me to check physical remote buttons, real playback, live TV and mirroring; distinguish observed results from unverified claims. Denied native screenshots are a limit, not permission to bypass capture protection. Help me register an unused LG Quick Access number and verify return from live TV. Home must remain LG Home.

No root, exploits, firmware writes, factory menus, system-package disabling/removal, Home interception, boot hooks, background watcher, broad DNS blocking or automatic privacy changes. Do not copy signed LG test identities or request extra privileges. If I separately request privacy changes, record actual before values and menu photos, get my app/feature preferences, and use only authorized ordinary reversible settings. Never promise zero risk or that the launcher stops all LG telemetry or content ads.

Finish with the exact installed version and SHA-256, local backup/capture locations, completed and pending checks, Quick Access instructions, Developer Mode renewal instructions and how to run restore.ps1 (or npm run tv -- restore) from the paired checkout. Explain that restore returns to native Home without removing packages and does not restore firmware or manual privacy toggles. Do not commit, push or publish my device-specific files or changes unless I separately ask you to publish reviewed non-sensitive changes.
```
